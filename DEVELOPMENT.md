# Local development

The local repo is the source of truth. Claude Design (claude.ai/design) receives changes through `/design-sync`.

## Setup

```sh
npm install   # also points git hooks at .githooks/
npm run serve # http://127.0.0.1:4321
```

Open `ui_kits/website/index.html`, `components/**/*.card.html`, `guidelines/*.html` and `templates/**/*.dc.html` to preview.

## Editing

- `tokens/*.css` - changes show on reload.
- `components/**/*.jsx`, `ui_kits/**/*.jsx` - previews load the compiled `_ds_bundle.js`, not the sources. Run `npm run build` after editing, then reload.
- A component change means updating all four files together: `.jsx`, `.d.ts`, `.prompt.md`, `.card.html`.

`index.html` is the book: README plus every `@dsCard` card and `@template` template, browsable like in Claude Design. It is generated by `scripts/build-book.mjs`, so `npm run build` after changing README.md or adding, renaming or regrouping a card or template. The pre-commit check fails when it is stale.

## GitHub Pages

The book is served by GitHub Pages: Settings - Pages - Deploy from a branch - `main` / `(root)`. `.nojekyll` must stay: without it Jekyll drops files starting with `_`, including `_ds_bundle.js`, and every card renders empty.

`scripts/build-ds-bundle.mjs` reproduces the Claude Design bundle format (v4) byte-for-byte. The pre-commit hook runs `npm run check` and blocks commits where the bundle is stale.

## Syncing to Claude Design

Run `/design-sync` in Claude Code. Do not upload local-only tooling: `package.json`, `package-lock.json`, `scripts/`, `.githooks/`, `node_modules/`, `DEVELOPMENT.md`, `.claude-plugin/`, `skills/`, `index.html`, `.nojekyll`, `LICENSE`.

## Claude Code plugin

The repo is also a Claude Code plugin marketplace (`.claude-plugin/`) with two skills. `design-system` applies the system in another project: it reads README.md and the sources from the plugin and copies tokens and components into that project. `linkedin-graphics` renders LinkedIn posts, carousels and the banner from `templates/` to PNG and PDF with headless Chrome (`skills/linkedin-graphics/scripts/render.mjs`, no npm dependencies).

Install it once, then use it from any project:

```
/plugin marketplace add <github-owner>/<repo>
/plugin install broniszewski-design@broniszewski
```

`plugin.json` has no `version` on purpose, so every pushed commit is a new version and `/plugin marketplace update broniszewski` picks it up.

Try local changes without installing: `claude --plugin-dir <path to this repo>`. Render every stock layout to check the templates still work:

```sh
R=skills/linkedin-graphics/scripts/render.mjs
node $R layouts linkedin-post
node $R layout linkedin-post 5 > /tmp/slide.html && node $R render linkedin-post /tmp/slide.html
```
